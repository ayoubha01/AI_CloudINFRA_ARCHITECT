# AI Infrastructure as Code Generator

An AI-assisted platform that converts natural-language infrastructure requirements into structured, validated Terraform code for AWS.

The project combines **Generative AI**, **Cloud Architecture**, **Infrastructure as Code**, and **DevSecOps validation** to make infrastructure generation easier, safer, and more understandable.

---

## Overview

Instead of writing Terraform manually, a user can describe the desired infrastructure in natural language:

```text
Create an AWS infrastructure in eu-west-2 with a VPC 10.0.0.0/16,
a public subnet, an Internet Gateway, a route to the Internet,
a Security Group allowing HTTP on port 80, and a t3.micro EC2 instance.
```

The application transforms that request through a controlled pipeline:

```text
Natural Language Prompt
        ↓
      LLM
        ↓
Structured Infrastructure JSON
        ↓
Zod Schema Validation
        ↓
Logical Dependency Validation
        ↓
Terraform Generator
        ↓
Terraform Code
```

The LLM does **not** generate the final Terraform directly.  
It only produces a structured infrastructure specification. The application then validates that specification and deterministically generates the Terraform code.

This design makes the system more predictable, testable, and secure than directly accepting arbitrary HCL generated by an AI model.

---

## Main Goals

The project aims to:

- Convert natural-language cloud requirements into Infrastructure as Code.
- Generate clean and reusable Terraform configurations.
- Validate AI-generated infrastructure before Terraform generation.
- Detect invalid relationships between cloud resources.
- Reduce hallucinations by restricting the AI to supported resource types.
- Provide a foundation for security checks, Terraform validation, cost estimation, and multi-cloud support.

## Current Features

### AI Infrastructure Generation

The user sends a simple prompt such as:

```json
{
  "prompt": "Create an AWS VPC with a public subnet, an Internet Gateway, a route to the Internet, a Security Group allowing HTTP, and an EC2 instance."
}
```

The AI converts it into a structured infrastructure model.

Example:

```json
{
  "provider": "aws",
  "region": "eu-west-1",
  "resources": [
    {
      "type": "vpc",
      "name": "main-vpc",
      "properties": {
        "cidrBlock": "10.0.0.0/16",
        "enableDnsSupport": true,
        "enableDnsHostnames": true
      }
    },
    {
      "type": "subnet",
      "name": "public-subnet",
      "properties": {
        "cidrBlock": "10.0.1.0/24",
        "availabilityZone": "eu-west-1a",
        "vpc": "main-vpc",
        "mapPublicIpOnLaunch": true
      }
    }
  ]
}
```

## Validation Layers

The application uses multiple validation stages.

### 1. AI Structured Output Validation

The LLM is restricted to a predefined infrastructure schema.

It cannot freely generate unsupported resource types.

### 2. Zod Business Validation

The generated infrastructure is checked with Zod.

Examples:

- Missing EC2 AMI
- Invalid resource type
- Missing VPC reference
- Invalid Security Group port
- Invalid property type
- Empty resource names

### 3. Logical Dependency Validation

The application verifies relationships between resources.

Examples:

```text
Subnet → VPC
Security Group → VPC
Internet Gateway → VPC
Route Table → VPC
Route → Internet Gateway
Route Table → Subnet
EC2 → Subnet
EC2 → Security Group
```

If a subnet references a VPC that does not exist, the request is rejected before Terraform generation.

Clone the repository:

```bash
git clone <repository-url>
cd ai-iac-generator/server
```

Install dependencies:

```bash
npm install
```

Create a `.env` file:

```env
LLM_API_KEY=your_api_key
LLM_MODEL=your_model
PORT=5000
```

Do not commit `.env`.

Start the development server:

```bash
npm run dev
```

The API will run by default on:

```text
http://localhost:5000
```

## Security Design

A key design principle of the project is:

> AI proposes the infrastructure, but the application controls what is accepted.

The LLM never directly executes Terraform and never directly deploys resources.

The infrastructure must pass:

```text
AI Structured Output
        ↓
Schema Validation
        ↓
Dependency Validation
        ↓
Terraform Generation
```

Future versions will also include security checks such as:

```text
HIGH    SSH 22 open to 0.0.0.0/0
HIGH    RDP 3389 open to the Internet
WARNING Publicly routable VPC CIDR
WARNING S3 bucket without recommended protections
WARNING Unrestricted outbound traffic
ERROR   Invalid AMI format
```

## Why This Project?

Infrastructure as Code is powerful, but designing cloud architectures and writing secure Terraform configurations requires significant expertise.

Large Language Models can simplify this process, but directly trusting AI-generated infrastructure introduces risks.

This project explores a safer approach:

```text
AI for understanding intent
+
Deterministic code for infrastructure generation
+
Validation for reliability and security
```

The objective is not to replace Cloud or DevOps engineers, but to provide an intelligent assistant that accelerates infrastructure design while preserving control, transparency, and validation.
